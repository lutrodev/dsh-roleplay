# Roleplay 创作预设

创作预设用于保存可复用的故事规则与写作任务，例如用户参与方式、角色自主性、连续性、场景推进、自检和输出要求。内置“示例预设”会判断场上人物当下的目标、做法和阻力，让对白、行动、反应与信息彼此作用；变化可以细微，不要求每轮冲突或反转。一个场景可以跨越多轮，每轮保持清晰的主要推进方向，同时允许行动、信息和关系变化伴随发生。重要选择、冲突与发现用场景展开，重复事务、等待和路程可以概述；转场会重新锚定必要的时间、地点、人物状态与未解决事项。

示例预设要求 Writer 依据既有人设、当前情境和用户意图，让主角持续说话、思考、判断和行动，不等待用户逐句代写。用户扮演主角时，仅把尚未表态、且会明显改变主角长期处境、核心目标或核心关系的最终决定留给用户；决定前的试探、犹豫和交流，以及方向明确后的执行与后果仍自然展开。结果可以是成功、失败或两者并存。人物立场与叙事事实彼此区分，已经造成的伤害与损失进入后续因果，但修复、惩罚、原谅或救赎不预设结论。

“配角心声”栏位是主角锚定叙事的受控例外：只在有明确收益且不会提前泄露应保留秘密时，短暂展示一名配角的内心，保持归属清楚并尽快回到当前叙事焦点。收束会在形成足够进展后停到用户仍能影响下一步的自然位置，不强行提问或制造悬念。成人亲密场景不作为内置示例预设的独立栏位，用户仍可在自己的预设中按需添加相关规则。

首次初始化会创建内置的“示例预设”并设为默认；之后新建预设会像新建文风一样直接进入空白编辑器，不再选择空白或示例起点。提示文本未编辑的旧版示例会保留资产、已有栏位 ID 与分组标签设置并升级内容；用户修改过提示文本的预设不会被覆盖。编辑器可以自由新增、删除、排序和调整栏位；每个栏位还能设置是否默认使用 `<section>`／`<item>` 分组标签，会话首次使用时继承该值，之后可在“回复资料”中独立调整。插件还支持把 SillyTavern Chat Completion 预设按语义转换为创作预设与独立文风。

Agent 模式更新预设时必须提交读取到的完整栏位数组，并保留每个栏位的 UUID、说明、正文、位置和分组标签布尔值；缺字段、错字段或无效 UUID 会明确报错，不会再静默生成新栏位 ID、清空内容或重置分组设置。
