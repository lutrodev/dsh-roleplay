# Roleplay 回复选项

启用后，主模型会在每次成功提交的 Roleplay 剧情回复中同时给出设定数量的主角后续消息。每项固定使用第三人称，以主角姓名或“他／她”为叙述主体，只写主角接下来的对白和／或行为；第一人称只可自然出现在主角的引号内对白中，不能作为叙述或行为主体。选项不以导演视角续写其他角色反应或预定行动结果。数量可设置为 1–5，默认 3 条；每条字数上限指导可设置为 1–200 个 Unicode 字符，默认 50，该值只告诉主模型“最多”多少字，不会按该设置拦截提交；每个编号还可填写一个不超过 40 个 Unicode 字符的可选方向关键词，例如“试探”“反抗”或“离开现场”。输入框数量始终与选项条数一致，留空的编号由模型自行选择不同方向。选项显示在最新回复的会话变量卡片下方，点击一项会原样发送并开始下一轮生成。

- 选项由当前主模型在同一次 `rp_commit_turn` 中生成，不会发起额外模型调用。
- 配置条数是模型生成目标和规范结果的最多条数，不再用“必须刚好 N 条”阻断整次剧情提交：至少有一条可用内容即可保存，超出的条目会截到配置数量，空白与重复项会被忽略。已知字段由扩展校验器规范化；模型额外附带的 `description` 等非权威注释也不会触发 `INVALID_ARGS`，但未知扩展命名空间仍会被 Core 拒绝。
- 每条字数上限只作为主模型 Prompt 指导，不写入 `minLength`／`maxLength`，提交与历史回放完全不按选项文本长度拒绝内容；Core 的整份 artifact 字节上限仍适用于所有提交数据。
- `user-controlled protagonist` 固定指向上下文中 `<section name="人设信息"><item name="我的人设">` 的内容，不把实际姓名或人设正文动态拼入选项 Schema；缺少该 item 或整个标签上下文时，模型从其余上下文与当前对话自行判断。
- 方向关键词按编号写入该次提交工具的动态 Schema，只指导对应选项的意图或策略；它不能覆盖既有事实与用户控制边界，也不会作为标题或标签直接拼入消息正文。
- 每个按钮前显示仅用于界面识别的数字编号；实际发送内容仍是按钮中的完整用户消息，不含编号。卡片右上角的齿轮可直接打开设置，每条末尾不再重复显示“发送”文字，也不提供隐藏正文、确认弹窗或“换一批”。
- 点击选项不会覆盖输入框中尚未发送的草稿；发送失败时可以直接重试。
- 只消费成功提交事件中的 `rp.reply-options` 扩展，不为普通讨论、拒绝、失败回复、开场白或子代理回复生成选项。
- 删除、编辑或重新生成消息时，选项会随当前有效对话回退或失效；插件不维护独立会话存储。

新配置默认启用，可在“设置 → Roleplay → 功能 → 对话”中的“回复选项”开关管理。已有配置升级后保持原选择，不会自动开启。条数、字数上限指导与关键词会作为一组原子保存，并由新建或重新打开的 Roleplay 对话使用；旧配置缺少字数指导时采用默认 50，缺少的关键词位置会补为空值，超出当前条数的位置不会进入运行时。历史提交中的 1–5 条选项仍可按事件日志安全回放。Host 实例只承载浏览器界面；Roleplay preset 内的运行时实例负责注册提交扩展。
